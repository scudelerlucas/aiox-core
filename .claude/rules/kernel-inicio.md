# Início de sessão — o que vale antes de qualquer arquivo ser tocado

1. **Memória:** ler os 10 resumos mais recentes de `memoria/` (fonte central, a primeira acessível: este repo se for o hub → `../Lucas-Contexto-Geral/memoria/` → GitHub `scudelerlucas/lucas-contexto-geral`; **soma-se** a ela `memoria/` deste repo, onde o fallback grava — os 10 são os mais recentes das duas fontes juntas, ordenados pelo nome). Inacessível → seguir sem, sem perguntar. **Fim de sessão com trabalho real:** gravar 1 resumo `memoria/AAAA-MM-DD--<repo>--<slug>.md` (≤40 linhas; feito · decisões · pendências · links · ferramentas · vetos aceitos; nunca segredos nem dados de clientes), commit + push na branch da sessão; hub não gravável → `memoria/` deste repo. Norma completa: `memoria-compartilhada.md`.
2. **PEP antes do trabalho:** classificar (CRIAR/ALTERAR/CONSULTAR/DECIDIR), definir o output-alvo, spec ≤15 linhas, síntese de 2–4 linhas. **Não aplicar** em prompt trivial, comando já explícito (`!atom`, `/forja5`, skill nomeada) ou emergência declarada — PEP em prompt trivial é violação. Norma: `prompt-engineering-protocol.md`.
3. **RADAR-4Z:** material substantivo novo, plano prestes a executar, incerteza declarada ou pedido de auditoria → micro-scan silencioso das 4 zonas; só aflora achado material. Norma: `forjar-4-zonas.md`.
4. **`main` protegida:** nunca `git push` para `main` — branch da sessão → PR → o operador revisa. Vale mesmo "só doc", mesmo validado. Única exceção: o operador pedir explicitamente, naquela conversa. Push que devolver `Bypassed rule violations` = regra quebrada, avisar na mesma resposta. Norma: `git-main-protegida.md`.
5. **Lei central da ARQUITETÔNICA:** `P = [T × A × S × N] ^C × R` — Posicionamento, Território, Arquétipo, Símbolos heurísticos, Narrativa, Coerência, Ritmo — relativo a um Adversário, sustentado por Prova, no slot da Ferida. Definições e termos proibidos: `arquitetonica-lei-central.md`; nunca de memória.
